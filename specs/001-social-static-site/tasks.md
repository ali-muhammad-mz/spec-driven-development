# Tasks: Social Static Site

**Input**: Design documents from `/specs/001-social-static-site/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Playwright browser checks are included because the implementation plan requires build and end-to-end verification.

**Organization**: Tasks are grouped by user story to document the implemented, independently testable increments.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1, US2, US3)
- Completed checkboxes document work already implemented in the current app

## Path Conventions

- **Static Next.js app**: `app/`, `components/`, `data/`, and `tests/` at repository root
- **Feature docs**: `specs/001-social-static-site/`
- **Static export output**: `out/` generated by `npm run build`

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies - starts immediately.
- **Foundational (Phase 2)**: Depends on Setup completion - blocks all user stories.
- **User Story 1 (Phase 3)**: Depends on Foundational phase completion.
- **User Story 2 (Phase 4)**: Depends on Foundational phase completion and uses shared header navigation.
- **User Story 3 (Phase 5)**: Depends on Foundational phase completion and uses shared header navigation.
- **Polish (Phase 6)**: Depends on all selected user stories being complete.

### User Story Dependencies

- **User Story 1 (P1)**: Can start after Foundational phase; no dependency on other stories.
- **User Story 2 (P2)**: Can start after Foundational phase; independent page, shared header.
- **User Story 3 (P3)**: Can start after Foundational phase; independent page, shared header.

### Within Each User Story

- Playwright checks document the independent verification target for the story.
- Mock data exists before page rendering.
- Page routes use reusable components and embedded data.
- Story is complete when its route, content count, and navigation check pass.

### Parallel Opportunities

- Documentation tasks T002-T005 can run in parallel.
- Configuration tasks T009-T011 can run in parallel after package setup.
- Foundational component/style tasks T013-T015 and T017-T018 can run in parallel once layout expectations are known.
- User Story 2 and User Story 3 can be implemented in parallel after the header and mock data exist.
- Story-specific Playwright tests T019, T025, and T029 can be authored in parallel with their corresponding pages.

## Implementation Strategy

### MVP First (User Story 1 Only)

1. Complete Setup and Foundational phases.
2. Complete User Story 1 homepage tasks.
3. Validate `/` shows the status box, 10 posts, and 3 suggested profiles.

### Incremental Delivery

1. Complete homepage MVP.
2. Add notifications route and header navigation.
3. Add chats route and header navigation.
4. Run build and Playwright verification across desktop and mobile.

### Parallel Team Strategy

1. One contributor completes project setup and shared shell.
2. Contributors split homepage, notifications, and chats route work after shared mock data exists.
3. Final contributor runs cross-story build, keyboard, and mobile verification.
